## Resultado funcional

La navegación lateral, el fondo crema, el café oscuro, la tipografía existente y las tablas compactas adaptan la referencia al catálogo y los estados reales. En móvil, la navegación se despliega y las filas se leen como tarjetas. Los editores laterales conservan el foco, ofrecen acciones al pie, bloquean envíos repetidos y advierten sobre cambios sin guardar.

- **Resumen:** tarjetas operativas enlazadas, pedidos por día, distribución por estado y entrega, productos y categorías más solicitados, períodos predefinidos/personalizados y comparación con el período anterior. Cuenta y actualización operativa quedan en secciones desplegables.
- **Productos:** búsqueda, filtros por categoría/estado, orden y paginación; crear/editar en panel lateral, foto mediante el flujo existente, existencia, activación, datos avanzados plegados, duplicación y retiro.
- **Categorías:** tabla compacta, búsqueda, creación/edición lateral y confirmación del impacto al desactivar.
- **Promociones:** tabla con búsqueda/estado, editor lateral, búsqueda de productos/categorías y selección que persiste al filtrar. Los productos retirados se quitan explícitamente. Se conserva la regla del mayor descuento sin acumulación.
- **Pedidos:** filtros operativos y rango de fecha solicitada; detalle con productos y acciones agrupadas. Cotización, pago, versiones y transiciones mantienen las reglas del servidor. Cancelar requiere confirmación.
- **Usuarios:** creación desplegable, tabla adaptable y permisos de propietaria existentes; contraseña inicial, cambio obligatorio, MFA y protección del último propietario conservados.

No se crearon pantallas vacías para funciones inexistentes, ni controles de exportación o cobro sin implementación respaldada.

## Semántica de los datos

La nueva API privada `/api/admin/analytics` requiere administración autenticada y usa `Cache-Control` privado sin almacenamiento. Solo devuelve agregados, sin nombres de clientes, teléfonos, direcciones o importes.

Los gráficos cuentan pedidos por **fecha de creación**, en `America/Guatemala`; sus estados son los **actuales**, no una reconstrucción del estado al cierre de cada día. El período admite hasta 366 días y rellena días sin pedidos con cero. Hoy se compara con la misma duración transcurrida del período anterior. La ausencia de datos previos se muestra sin inventar porcentajes.

Rankings y distribución por entrega excluyen pedidos cancelados y pagos reembolsados. Productos/categorías usan snapshots del pedido y conservan sus presentaciones; no suman bolsas como piezas ni reconstruyen datos desconocidos. Se muestran hasta 8 productos y 12 combinaciones de categoría/presentación. Las tarjetas de operación actual no están limitadas por el período histórico seleccionado. Los filtros de Pedidos usan la **fecha solicitada**.

**Pedidos no equivale a ventas cobradas.** El panel no presenta ingresos ni presupone que seleccionar un método de pago verifica fondos. La analítica y el monitoreo propios del Ticket 12 permanecen en su rama hasta la integración autorizada.

### Reproducción

Ejecutar únicamente en una base desechable cuyo nombre sea exactamente `guteli_test`; los comandos E2E reinician y siembran esa base. Definir `DATABASE_URL_TEST` y `DATABASE_URL` con la URL de esa instancia aislada.

```sh
npm test
npm run test:integration
ADMIN_UX_FULL=1 ./node_modules/.bin/playwright test --config=playwright.admin-ux.config.ts
./node_modules/.bin/playwright test --config=playwright.admin-ux.config.ts
ADMIN_UX_LIVE=1 ./node_modules/.bin/playwright test --config=playwright.admin-ux.config.ts
npm run test:e2e:live
npm run test:e2e:unavailable
npm run lint
npm run typecheck
npm run build
```

Para las suites `test:e2e:live` y `test:e2e:unavailable`, exportar también secretos ficticios `BETTER_AUTH_SECRET`, `RATE_LIMIT_SECRET`, `RECEIPT_TOKEN_SECRET`, `TRUSTED_PROXY_HOPS=1` y `BETTER_AUTH_URL` con el origen de cada servidor (`http://127.0.0.1:3101` y `http://127.0.0.1:3102`, respectivamente). Sus configuraciones existentes no proporcionan por sí solas el entorno de seguridad del checkout.

Para el build local definir también `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, `RATE_LIMIT_SECRET` y `RECEIPT_TOKEN_SECRET` con valores ficticios válidos. No son instrucciones de configuración de producción.

## Revisión y correcciones

Una revisión independiente de solo lectura detectó pérdida de seguimiento de cambios en selección masiva, desactivación de categorías y operaciones simultáneas; también detectó selección de productos retirados y desincronización del rango al navegar atrás. Se corrigieron y se añadieron comprobaciones de navegador. La revisión final no identificó nuevas regresiones concretas en esas correcciones.

El navegador permitió corregir además la pérdida de la capa modal al reordenar una fila después de guardar: el diálogo ahora usa un portal estable dentro del shell administrativo. La navegación a un producto duplicado reinicia su editor por identidad. Se ajustaron selectores E2E a la nueva UI y al contenido de rutas conservado por Next.js; no se relajaron las comprobaciones de negocio.
