# Documentation Rules

Maintain:

- Repository README with only verified commands
- `AI/AI-EOS` as the single engineering handbook
- Append-only decision log
- Obsidian project context, architecture, requirements, current state, roadmap, learnings, testing, deployment, and session log
- Artifact reports based on commands or rendered evidence actually produced
- Runbook and API documentation only when those systems exist

Rules:

- The application must not import, read, or require the Obsidian vault.
- Do not duplicate canonical decisions across competing locations. Link to the canonical note when possible.
- Mark pending reports as not run; never present placeholders as evidence.
- Use project-relative repository paths.
